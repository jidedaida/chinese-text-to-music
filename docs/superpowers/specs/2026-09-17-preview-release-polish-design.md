# 字谱预览发布与交互收尾设计

**日期：** 2026-09-17  
**状态：** 待用户审阅  
**目标分支：** `codex/implement-mvp`

## 1. 目标

在不合并 `main` 的前提下，将当前浏览器 MVP 发布为可公开访问的 GitHub Pages 测试版，供用户跨设备试听和验收。同时补齐既有产品设计中尚未完整实现的超长输入反馈、音序器声部轮廓、屏幕阅读状态与首屏加载性能。

本轮不新增作曲规则、账户、后端、云端存储、分析统计、正式域名或协作功能。音乐映射版本与曲谱结构保持不变。

## 2. 发布模型

采用单一预览环境：

```text
codex/implement-mvp
→ GitHub Actions 验证与构建
→ GitHub Pages 测试网址
→ 用户试听与反馈
→ 分支继续修改并自动更新预览
→ 用户最终确认后另行创建 PR、合并 main
```

预览站始终跟随 `codex/implement-mvp`。`main` 在用户试听确认前保持不变。预览页面显示“测试版”标识，避免与正式版本混淆。

GitHub Pages 是首选发布方式。若当前仓库或账户无法启用 Pages，则停止自动部署并报告具体限制，再采用独立静态托管作为后续回退方案；不得静默改用其他公开服务。

## 3. Pages 子路径与资源寻址

GitHub Pages 的站点基路径为：

```text
/chinese-text-to-music/
```

Vite 构建通过 `VITE_BASE_PATH` 接收该路径，本地开发默认使用 `/`。HTML、JavaScript、CSS 与音频采样都必须使用构建时基路径，禁止继续硬编码 `/audio/...`。

音频采样 URL 从 `import.meta.env.BASE_URL` 派生。发布构建必须验证钢琴、提琴和大提琴采样均能在仓库子路径下访问，避免页面可打开但播放回退为合成音色的假成功。

## 4. 加载性能

首屏只加载工作台界面与必要状态逻辑：

- 完整拼音词典在用户第一次点击“生成音乐”时动态加载。
- Tone.js、乐器与实时音频引擎在第一次播放或试听时动态加载。
- 离线导出模块在第一次下载 WAV 时动态加载。
- 已加载模块在当前页面会话内复用，不因重复点击再次下载。

目标是将完整拼音词典和 Tone.js 从首屏入口包中拆出。构建验证记录各 JavaScript 分块体积，并断言入口包不包含完整词典资源；不通过修改警告阈值掩盖体积问题。

## 5. 预览版本标识

构建环境使用 `VITE_RELEASE_CHANNEL=preview`。预览构建在页面头部显示：

```text
测试版 · PREVIEW
```

本地开发可以显示相同标识，正式 `main` 构建默认隐藏。该字段只影响界面，不进入 `Score`、音乐种子或 `musicHash`。

## 6. 超长输入反馈

输入仍按汉字、字母和数字统计有效字符，范围保持 10～300：

- 301 个及以上有效字符时禁止生成，不截断原文。
- 字数显示使用错误色，并为文本框设置可访问的错误状态。
- 明确显示超出数量、第 301 个有效字符和一段短的原文片段。
- 页面提供“定位超出部分”操作，将文本框光标或选区移动到第 301 个有效字符对应的原文位置。
- 删除到 300 个有效字符以内后，错误状态立即消失。

定位逻辑必须使用原文索引，兼容标点、连续空白和 NFC 合成字符，不得直接用规范化文本下标切割原文。

## 7. 二维音序器声部轮廓

保留现有四色，在 Canvas 中增加用户选定的 A 方案语义轮廓：

| 声部 | 颜色 | 轮廓 |
|---|---|---|
| 主旋律 | 砖红 | 圆角实心 |
| 和声 | 紫色 | 双线、浅色填充 |
| 贝斯 | 绿色 | 实心、加厚底边 |
| 轻打击乐 | 金黄 | 菱形标记 |

当前词语对应的主旋律音符继续使用外层高亮。轮廓变化只影响绘制，不改变事件、轨道、作曲结果或音乐哈希。

Canvas 外的 `aria-live` 状态改为可读内容：

```text
当前词语“星光”，时间 12.4 秒，声部“主旋律”
```

不得向屏幕阅读器朗读内部 `token-0` 一类标识。

## 8. 自动验证与部署

新增 GitHub Actions Pages 工作流，触发条件为：

- 推送到 `codex/implement-mvp`；
- 手动触发。

同一分支只保留最新一次部署运行，旧运行允许取消。流水线顺序：

1. 检出代码并安装固定版本 Node/npm 依赖。
2. 校验 23 个授权采样文件及哈希。
3. 运行全部 Vitest 单元与组件测试。
4. 安装 Playwright Chromium 并运行浏览器端到端测试。
5. 运行 300 字作曲性能基准。
6. 使用 Pages 基路径与 `preview` 发布通道构建静态站点。
7. 上传 Pages artifact 并部署。

任何步骤失败都不得更新预览站，上一版成功部署继续可用。Windows Edge 门禁保留为本地发布验证，不要求 Linux Pages 工作流安装 Edge。

工作流只授予读取仓库、写入 Pages 和获取部署身份所需的最小权限。不创建额外密钥，不把原文、日志或音频结果发送给第三方。

## 9. 隐私与失败处理

- 预览站不加入账户、数据库、分析统计、广告或追踪脚本。
- 输入原文、规范化 token、曲谱与 WAV 仍只存在于用户浏览器。
- 网络请求仅允许站点静态资源与随站点发布的音频采样。
- 采样加载失败时继续执行已实现的一次重试和合成音色回退，并显示可读提示。
- 动态模块加载失败时保留最近一次成功曲目，显示重试信息，不清空用户原文。
- Pages 发布失败时报告失败步骤与日志入口，不修改 `main`。

## 10. 测试与验收

### 10.1 单元与组件测试

- 第 300、301 个有效字符以及混合标点、空白、NFC 字符的原文定位。
- 超长错误提示、可访问状态和“定位超出部分”行为。
- 四种 Canvas 轮廓分别调用正确绘制路径。
- 屏幕阅读状态包含真实词语、时间和声部，不含内部 token ID。
- `preview` 标识不影响 `Score` 与 `musicHash`。
- 动态模块只初始化一次，失败后允许重试。

### 10.2 构建与浏览器测试

- 本地 `/` 与 Pages `/chinese-text-to-music/` 两种基路径都能打开。
- 所有 JavaScript、CSS 和 23 个音源 URL 均返回成功状态。
- 入口包不包含完整拼音词典或 Tone.js 音频引擎。
- 在 Pages 子路径完成输入、生成、快速点词试听、暂停、停止、参数重生成与 WAV 下载。
- 页面刷新回到空白初始状态。
- 网络请求体不包含用户原文。
- GitHub Chromium 门禁通过；Windows Edge 门禁在正式合并前再次通过。

### 10.3 预览站验收

公开测试网址必须满足：

- 页面明确显示测试版标识。
- 控制台与网络面板没有资源 404。
- 四声部可播放，采样音色正常；失败时有合成音色回退。
- 点词试听、同步高亮和 WAV 下载工作正常。
- 分支后续推送能够自动更新同一预览网址。

用户完成主观试听并确认后，才进入创建 PR、合并 `main` 和正式发布的下一阶段。
