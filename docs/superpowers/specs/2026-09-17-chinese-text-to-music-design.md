# 中文文字转音乐：产品与技术设计

- 日期：2026-09-17
- 状态：设计已讨论通过，等待书面规格复核
- 范围：第一版浏览器应用

## 1. 产品目标

构建一个运行在桌面浏览器中的“二维音序器 + 实时合成器”。用户输入以中文为主的 10～300 个有效字符，应用按照固定、可解释且可复现的规则生成一首有明确起止的纯音乐短曲，并允许播放、文字与音符同步定位以及下载 WAV。

产品的核心承诺是：在相同算法版本下，相同文本和相同参数得到相同的规范化曲谱。生成过程全部在浏览器本地完成，不上传原文、曲谱或音频，也不依赖运行时 AI API。

## 2. 第一版非目标

- 不提供逐音符编辑、拖动音符或专业 DAW 功能。
- 不提供多人协作、账号、云端保存或作品社区。
- 不提供 MIDI 导出。
- 不提供随机变奏或“换一个版本”。
- 不承诺手机端完整操作体验。
- 不要求不同浏览器导出的 WAV 文件逐字节一致。

## 3. 已确认的产品决定

### 3.1 输入与生成

- 支持 10～300 个有效字符；汉字、字母和数字计入长度，空白与标点不计入。
- 输入阶段不实时生成或发声。用户点击“生成”后，一次性计算完整曲目。
- 只有空白或标点时禁止生成；超过 300 个有效字符时不截断，而是提示并定位超出部分。
- 英文、数字和生僻字仍可获得稳定音乐身份；没有声调信息时跳过声调方向约束。
- 修改文字或参数后，最近一次成功曲目继续可播放，但标记为“待重新生成”。

### 3.2 曲目与交互

- 第一版生成主旋律、和弦铺底、贝斯和轻打击乐四个声部。
- 默认风格为钢琴室内乐：钢琴演奏主旋律、弦乐负责和弦、低音提琴承担贝斯、轻柔打击乐提供节奏。
- 情绪选项为“自动、明亮、平静、忧郁”，不设置“紧张”。
- 用户可调节调性、速度、情绪与整体音色。用户显式选择优先于情绪推断出的默认值。
- 调性提供 12 个主音以及大调、自然小调、大调五声音阶和小调五声音阶；默认采用 C 大调五声音阶。
- 速度允许 60～140 BPM 的整数值，默认 84 BPM。情绪可以给出建议值，但一旦用户手动调整，速度以用户值为准。
- 整体音色第一版固定提供“钢琴室内乐、柔和电子、极简钢琴”三个预设，默认使用“钢琴室内乐”。
- 播放时同步高亮当前词语及其主旋律音符；点击词语可移动播放头并从相应位置试听。
- 第一版支持浏览器本地渲染并下载 44.1 kHz、16-bit、双声道 WAV。

### 3.3 可复现性

- 相同规范文本、相同参数、相同 `mappingVersion` 与 `composerVersion` 必须产生相同的规范化 `Score`。
- 重复点击“生成”不引入随机数或变奏。
- 版本号参与种子计算；未来算法升级使用新版本号，不悄悄改变旧规则。
- 跨设备保证曲谱事件一致。浮点计算、编码器或音频实现差异可能造成 WAV 二进制差异，但不改变音符、节奏和编曲内容。

## 4. 页面与用户流程

### 4.1 三栏工作台

第一版采用方案 B：

- 左侧约 30%：中文输入与阅读区，显示有效字数、分词状态和播放中的词语高亮。
- 中央约 50%：二维钢琴卷帘。横轴表示时间和词序，纵轴表示音高；音符长度表示时值，颜色与轮廓共同区分声部。
- 右侧约 20%：调性、速度、情绪、整体音色以及“生成”按钮。
- 底部固定栏：播放、暂停、停止、时间进度、音量和“下载 WAV”。

目标桌面宽度不低于约 1024 px。第一版优先支持当前稳定版 Chrome 与 Edge；其他浏览器或窄屏设备显示兼容性提示。

### 4.2 主流程

```text
输入文字
→ 调整参数
→ 点击生成
→ 一次性得到完整曲目
→ 播放并观察文字/音符同步
→ 下载 WAV
```

### 4.3 页面状态

```text
等待输入 → 已修改 → 生成中 → 可播放
                         ↘ 播放中 / 已暂停
                         ↘ 导出中
                         ↘ 错误
```

- “生成中”禁止重复生成。
- “导出中”禁止重复导出，但不清除曲谱。
- 新生成失败时保留最近一次成功曲目。
- 播放、定位和导出始终引用最近一次成功生成的同一份 `Score`。

## 5. 确定性文字到音乐算法

### 5.1 文本规范化

界面始终保留原始文本。音乐计算使用单独的规范文本：

1. Unicode 规范化为 NFC。
2. 统一等价空白和中英文标点。
3. 使用随应用发布并带版本号的固定转换表，将繁体身份转换为简体身份。
4. 保留字母和数字；不识别的可见字符按其 Unicode 码位参与身份计算。

因此“春風”和“春风”共享音乐身份，但界面分别保留用户输入。实现不得使用会随操作系统或浏览器版本变化的隐式语言规则。

### 5.2 固定分词与读音

- 使用随应用发布的固定词典和确定性最长匹配算法。
- 未命中的中文内容回退为单字 token。
- 多音字优先使用固定词语读音表，未命中时使用该字的固定默认读音。
- 不使用 `Intl.Segmenter` 作为决定曲谱的分词来源，避免不同 ICU 版本导致结果漂移。
- 每个 token 保存原文起止位置、规范形式、拼音、声调与 token ID。

### 5.3 词语音乐身份

```text
wordSeed = SHA-256("mapping-v1|" + 规范词语)
```

摘要字节按固定槽位解释：

- 基础音级与允许音域；
- 节奏模板；
- 上行、下行或拱形等旋律轮廓；
- 八度位置；
- 力度；
- 连奏、断奏或重音等演奏法。

SHA-256 解决任意新词的稳定身份问题，不需要维护“所有词语到旋律”的巨大数据库。它提供近乎不会冲突的数字身份；由于可听音乐参数是有限集合，不承诺所有不同词语在人耳听感上都完全不同。

### 5.4 声调与音乐性

- 一声倾向平稳或小幅延伸。
- 二声倾向上行。
- 三声倾向先下后上或延迟回升。
- 四声倾向下行。
- 轻声倾向短、弱并靠近前一音。

声调只构成软约束。最终音高必须吸附到当前调式，并遵守声部音域、和声与可唱性限制；发生冲突时音乐性优先。

### 5.5 从动机到乐句

- 每个词生成一个基础动机。
- 相同词保留相同节奏骨架与相对音程轮廓。
- 为融入当前和声，动机可以整体移调，但不得改变其核心节奏与轮廓身份。
- 逗号产生短呼吸，句号、问号和感叹号形成终止式，换行开始新乐段。
- 连续重复结构可在后续出现时合并为一次主陈述和一次缩短回应，但每个 token 仍保留到对应事件的追溯关系。

### 5.6 完整编曲

主旋律确定后，`Composer` 依次生成：

1. 符合调式和句子终止位置的和弦轨；
2. 跟随和弦根音、避免与主旋律拥挤的低音轨；
3. 根据速度、情绪和句子重音生成的轻打击乐轨。

伴奏仅依赖主旋律、句子边界、用户参数和版本化规则，不调用随机数。

### 5.7 全文种子与曲目时长

```text
compositionSeed = SHA-256(
  "composer-v1|" + 规范全文 + 规范化参数
)
```

令 `n` 为 10～300 之间的有效字符数，目标时长为：

```text
targetSeconds = round(30 + 270 × (n - 10) / 290)
```

最终结果限制在 30～300 秒。长文本通过压缩停顿、提高单位拍内的动机密度和合并连续重复结构接近目标时长，不删除正文 token，也不改变其顺序。

## 6. 技术架构

### 6.1 技术栈

- TypeScript、React 与 Vite 构建单页应用。
- Canvas 2D 绘制钢琴卷帘，只渲染当前可见时间区域。
- Tone.js 管理时钟、采样器和 Web Audio 调度。
- 钢琴与弦乐使用随站点发布的开源采样；贝斯与轻打击乐使用 Web Audio 合成。
- 采样必须为 CC0 或允许再分发并可提供署名的许可证；来源和许可证记录在仓库的 NOTICE 文件中。
- 无后端、数据库或运行时 AI 服务。

### 6.2 模块边界

```text
React 界面
   ↓
TextAnalyzer
   ↓
MotifMapper
   ↓
Composer
   ↓
Score
  ↙       ↓        ↘
Canvas   AudioEngine   WavExporter
```

#### `TextAnalyzer`

负责文本规范化、简繁身份转换、固定分词、拼音与声调解析。它不生成音乐。

#### `MotifMapper`

把单个规范 token 映射为基础音乐动机。它是无副作用纯函数，相同输入与版本永远返回相同结果。

#### `Composer`

组织乐句、调式、和声、低音、打击乐与时长压缩。它只输出数据，不直接播放声音或操作界面。

#### `Score`

是音序器、播放和导出的唯一曲谱数据源。规范结构包含：

```ts
interface Score {
  schemaVersion: string;
  mappingVersion: string;
  composerVersion: string;
  seed: string;
  musicHash: string;
  settings: ResolvedSettings;
  durationSeconds: number;
  tokens: Token[];
  tracks: Track[];
  noteEvents: NoteEvent[];
}

interface NoteEvent {
  id: string;
  tokenId: string | null;
  trackId: string;
  startBeat: number;
  durationBeats: number;
  midi: number;
  velocity: number;
}
```

主旋律事件必须关联 `tokenId`；纯伴奏事件可以使用 `null`。规范化序列化采用固定字段顺序与稳定数组排序，用于比较曲谱哈希。

`musicHash` 只对影响声音的规范 token、参数、轨道和事件计算，不包含原始文字、显示字符或原文位置。因此简繁原文可以保留不同显示内容，同时得到相同的音乐哈希。

#### `AudioEngine`

负责音频上下文初始化、采样加载、播放、暂停、停止、定位和音量。浏览器首次用户手势后才初始化音频上下文。

#### `SequencerCanvas`

负责绘制、滚动、缩放、播放头和点击命中测试，不修改 `Score`，也不包含作曲规则。

#### `WavExporter`

从 `Score` 离线调度与实时播放相同的乐器配置，输出 44.1 kHz、16-bit、双声道 WAV。

## 7. 音色与资源策略

- 采样按声部延迟加载；生成曲谱不依赖采样是否加载完成。
- 钢琴或弦乐采样失败时自动重试一次。
- 重试失败后使用内置合成兼容音色，并显示非阻塞提示。
- 整体音色预设只改变乐器与效果参数，不改变文字分词、动机身份或曲谱时序。
- 三个音色预设及其参数均带版本号；默认预设为“钢琴室内乐”。

## 8. 异常、性能与隐私

### 8.1 异常处理

- 生成失败保留最近一次成功曲目，并提供可读错误信息和重试入口。
- 浏览器拒绝启动音频时提示用户再次点击播放解锁，不循环请求权限。
- 非目标浏览器、Web Audio 缺失或 WAV 导出不可用时显示兼容性说明。
- 导出失败不清除 `Score`；内存不足时建议关闭其他标签页后重试。

### 8.2 性能目标

- 在项目记录的 Chromium 性能基准环境中，300 字纯曲谱计算以连续 10 次运行的中位数不超过 1 秒为目标；首次采样下载时间单独显示且不计入该指标。
- Canvas 只绘制可见区域，并将静态网格与动态播放头分层。
- 五分钟 44.1 kHz、16-bit、双声道 WAV 约为 50 MB。导出显示预计耗时和不确定进度指示，不伪造精确百分比。
- 资源文件采用内容哈希缓存；应用更新时版本化失效。

### 8.3 隐私

- 原文、token、曲谱和 WAV 均留在浏览器本地。
- 不发送包含原文或曲谱的网络请求。
- 第一版不默认接入分析、广告或追踪服务。
- 静态音色请求不得携带文本内容。

### 8.4 可访问性

- 声部同时使用颜色、轨道标签与不同音符轮廓区分。
- 生成、播放、暂停、停止和导出均提供可聚焦按钮与键盘操作。
- Canvas 外提供当前词语、时间和声部的可读状态，供屏幕阅读器读取。
- 动画遵守 `prefers-reduced-motion`。

## 9. 测试策略

### 9.1 单元与固定样本

- 验证 Unicode、简繁身份、分词、多音字、标点、生僻字、英文和数字。
- 验证“春风”与“春風”得到相同音乐身份。
- 验证相同 token 在相同版本下得到相同基础动机。
- 覆盖 10 字和 300 字边界，以及空白、纯标点和超长输入。

### 9.2 属性测试

批量生成文本并验证：

- 相同输入、参数和版本的规范化 `Score` 哈希一致。
- 所有音符属于选定调式且位于所属声部音域。
- 时间、时值与力度不存在负数、越界或 `NaN`。
- 曲目时长位于 30～300 秒。
- 每个有效 token 至少关联一个主旋律事件或一个明确的合并回应事件。

### 9.3 黄金曲谱

为短诗、散文、简繁对照、多音字、混合字符和 300 字长文本保存版本化标准 `Score`。任何意外曲谱变化必须让测试失败；有意升级需要新版本和新黄金样本。

### 9.4 浏览器端到端测试

使用 Playwright 在 Chrome 与 Edge 验证：

```text
输入 → 生成 → 播放 → 同步高亮
→ 点击词语定位 → 修改参数出现待生成提示
→ 重新生成 → 下载 WAV
```

同时覆盖键盘操作、连续快速点击、采样加载失败、合成音色回退和页面刷新。

### 9.5 音频验证

- WAV 文件头、采样率、位深、声道和时长正确。
- 输出不是静音，峰值不过载且无明显削波。
- 四个声部都有预期事件。
- 实时播放与离线导出引用相同 `Score` 和乐器配置。

## 10. 第一版验收标准

- 10～300 个有效字符均可生成完整曲目。
- 在记录的 Chromium 性能基准环境中，300 字纯曲谱计算连续 10 次运行的中位数不超过 1 秒。
- 相同文本、参数和算法版本的规范化 `Score` 哈希一致。
- 播放中的文字与音符高亮目标误差不超过约 50 ms。
- 生成结果包含主旋律、和弦、贝斯和轻打击乐四个声部。
- WAV 可被常见桌面播放器正常打开，且内容与页面播放使用同一曲谱。
- 浏览器网络请求不包含原文、token 或曲谱。
- 采样失败、导出失败和不支持的浏览器均显示可理解提示，不出现空白页或数据丢失。

## 11. 交付边界

本设计文档覆盖一个可独立交付的第一版：本地文字分析、确定性作曲、四声部播放、二维音序器、同步高亮和 WAV 导出。账号、云存储、作品分享、移动端完整适配、逐音符编辑、MIDI 和随机变奏均在第一版之后单独评估，不进入本次实现计划。
