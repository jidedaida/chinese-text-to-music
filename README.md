# 中文文字转音乐

一个计划运行在浏览器中的“二维音序器 + 实时合成器”：中文词语按照稳定、可解释的固定规则转换成音符，并组成一首有明确起止的短曲。

## 当前已确认的产品方向

- 输入粒度：词语与句子构成乐句，而不是简单的一字一音。
- 旋律原则：音乐性优先；普通话声调提供上升、下降等软约束，最终音符吸附到选定音阶。
- 词语身份：规范词语经过带版本号的 SHA-256 映射，生成稳定的起始音、节奏、音色、力度与装饰参数。
- 简繁处理：界面保留原文；计算音乐身份时统一为简体规范形式，因此“春风”和“春風”共享音乐身份。
- 曲目结构：按全文顺序生成完整曲目，不做固定循环。
- 第一版长度：以中文为主的 10～300 个有效字符，面向诗歌、短文和文案；汉字、字母和数字计数，空白与标点不计数。
- 用户控制：提供调性、速度、整体音色和情绪倾向等基础调节，不做逐音符编辑。
- 情绪推断：使用本地规则、标点、句长和小型情绪词典生成默认情绪，用户可以覆盖。
- 运行方式：核心映射、情绪规则和 Web Audio 合成都在浏览器本地完成，不调用 AI API。
- 主界面布局：采用方案 B 的三栏工作台，左侧显示并编辑原文，中央以二维音序器为主体，右侧集中放置参数控制；底部固定播放与导出栏。
- 生成方式：输入文字时不实时重算；用户点击“生成”后，一次性生成完整曲目，再由用户控制播放。
- 音序器坐标：采用钢琴卷帘表达，横轴对应时间与词序，纵轴对应音高；音符长度表示时值，颜色区分声部。
- 编曲层次：第一版生成主旋律、和弦铺底、贝斯和轻打击乐四个声部；文字直接驱动主旋律，其余声部围绕整体结构与情绪生成。
- 可复现性：相同文本、相同参数与相同算法版本必须生成完全相同的曲目，不在重复生成时引入随机变奏。
- 文字联动：播放时同步高亮当前词语及其对应音符；点击词语可定位播放头并从该位置试听，但不提供逐音符编辑。
- 导出能力：第一版支持在浏览器本地离线渲染并下载 WAV，不包含 MIDI 导出。
- 设备范围：第一版优先支持桌面端 Chrome 与 Edge，以保证 Web Audio、WAV 渲染和大画布音序器体验；手机端不承诺完整功能。
- 默认风格：采用钢琴室内乐编制，以钢琴演奏主旋律、弦乐铺底、低音提琴承担贝斯，并加入轻柔打击乐；右侧面板可切换少量整体音色预设。
- 情绪控制：提供“自动、明亮、平静、忧郁”四项；自动模式使用本地规则推断，其余选项覆盖推断结果，不设置“紧张”模式。
- 曲目时长：随文本长度增长并限制在约 30～300 秒；长文本通过提高音符密度、压缩停顿和合并重复结构控制时长，不截断正文。
- 音频引擎：采用混合方案。独立 TypeScript 模块负责确定性作曲；钢琴与弦乐使用随站点分发的开源采样，贝斯与轻打击乐使用 Web Audio 合成。

## 当前算法轮廓

```text
原始文本
→ Unicode 与简繁规范化
→ 固定版本中文分词
→ 固定版本拼音与声调解析
→ SHA-256 词语身份
→ 多维音乐参数生成
→ 声调约束旋律方向
→ 标点与句子组织乐段
→ Web Audio 实时播放
```

## 本地运行

```bash
npm install
npm run dev
```

使用桌面版 Chrome 或 Edge 打开 Vite 显示的本地地址。所有文字分析、作曲、播放和 WAV 渲染都在浏览器中完成。

## 验证

```bash
npm run verify
```

该命令检查采样文件哈希、单元与组件测试、生产构建、Chromium 端到端流程和 300 字作曲性能。Windows 发布前另运行：

```bash
npm run test:e2e -- --project=edge
```

## 音源许可

钢琴、提琴采样的来源和 CC BY 3.0 署名见 `NOTICE.md`。贝斯与轻打击乐由 Web Audio 实时合成。

## 状态

第一版实现包含确定性中文文字分析、四声部作曲、二维音序器、实时播放、文字同步高亮和 WAV 下载。

## GitHub Pages 测试版

`codex/implement-mvp` 每次推送都会在完整验证通过后更新测试版：

https://jidedaida.github.io/chinese-text-to-music/

测试版页面会显示“测试版 · PREVIEW”。它没有账户、分析统计或后端；输入原文、曲谱和 WAV 只存在于当前浏览器。

本地复现 Pages 构建与浏览器流程：

```bash
npm ci
npm run verify:preview
```

本地与 CI 使用 Node 24，并通过 `npm ci` 安装锁定依赖。首次启用 GitHub Pages 时，请在仓库 `Settings → Pages` 的 `Build and deployment` 中将 `Source` 设为 `GitHub Actions`。

Windows 正式合并前仍需执行：

```bash
npm run test:e2e -- --project=edge
```
